# Codebase audit — 2026-09-24

Baseline: `d3c5d0b1ae2c76e6006f6b1c3cf45afb4de46bae` (main).

## Scope

All 1,186 tool pages are inventoried; first-party JavaScript and inline scripts are parsed; emitted HTML routes/assets are checked. Shared infrastructure and selected high-risk implementations are reviewed and regression-tested. This is **not certification of every algorithm, format, browser or input combination**.

A successful build is not a functional test. `unverified` means output correctness has not been established for all cases. `blocked` means a known implementation or dependency defect prevents use.

## Reproducible verification

`npm test` covers arithmetic vectors, malicious/invalid input rejection, spreadsheet chains/ranges/cycles, CSV escaping, catalog uniqueness, portable links, blocked-page safety and all first-party JS/inline-script syntax. The prepared working copy passed 35 tests.

`npm run typecheck`, `npm run build` and `npm run check:dist` passed in the working copy: 1,186 tool pages plus homepage and static catalog, with zero missing local href/src targets. Consult the PR's Actions checks for the final committed revision's results.

Browser regressions cover root/subpath navigation, filters/search/error states, storage denial, responsive overflow, static no-JavaScript navigation, actual JPEG signatures, stale conversion output, reset races, MIME rejection, URL cleanup, spreadsheet dependencies and representative category startup. The local browser environment blocks HTTP navigation; that limitation is not recorded as a product pass. Actions supplies browser results and screenshots.

## Remaining work — not concealed

1. Implement and independently test the 187 disabled operations. Cryptography needs standard vectors and authenticated-failure cases; PDF/archive/audio output needs real parsers/decoders, round trips and corrupt inputs. Renaming raw bytes is not an implementation.
2. Restore missing vendors from authentic upstream packages with integrity/license review. Other tools still use external CDNs. Catalog network labels are heuristic hints, not a complete network/privacy proof.
3. Add golden fixtures and negative cases for every remaining usable tool. Shared fixes do not repair all independent converters or pipelines. Existing HTML-string rendering and per-tool resource ownership need further review; the project is not certified XSS-free or leak-free.
4. Add Firefox/WebKit testing, full accessibility audits, fidelity/performance benchmarks and large-file/device-memory tests. The pixel limit is checked after browser decode and does not prevent all decode-time memory exhaustion.
5. Offline caching is not implemented. Local computation is not an offline/privacy guarantee. Baseline package metadata said MIT but no LICENSE file was present; ownership and intended license text must be confirmed by the maintainer.

## Re-enabling a tool

Implement the real operation, restore required assets, add algorithm/format and browser tests, and regenerate the catalog. Remove an AUDIT_UNAVAILABLE marker only with evidence. Keep the status unverified unless a future policy explicitly defines verified coverage. The registry preserves historical findings; it is not an automatic certification mechanism.
